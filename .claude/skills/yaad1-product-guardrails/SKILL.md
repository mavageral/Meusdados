# Yaad1 Product Guardrails

Before adding a feature, state:
1. Which user problem does it solve?
2. Which moment in ROTA does it support?
3. What is the smallest clear next action?
4. What evidence or real-world result should it create?
5. How does it behave offline, after interruption, and when AI is unavailable?
6. What data does it read/write, and what consent is needed?

## UX rules
- One dominant action per screen.
- Today screen answers “what now?” within seconds.
- Keep full schedule and analytics secondary.
- Prefer interactive teaching objects to walls of text.
- Use progressive disclosure; do not flatten every module into one dashboard.
- Use color semantically and not as the sole status signal.
- Preserve dark/orange/green design vocabulary, with controlled glass and glow.
- Provide accessible alternatives to gestures, voice, color, and motion.

## Evidence rules
- Simple activity: acknowledgment may suffice.
- Study: lesson/context + learner action + evidence + evaluation state.
- Deliverable: artifact/reference and acceptance criteria.
- Never convert `evaluation_unavailable` into a passing score.
- Keep `declared`, `submitted`, `evaluating`, `verified` distinct.

## ROTA link
Where supported by evidence, connect action to concept/skill → goal/front → opportunity. Do not invent links to a target just to motivate the user.

## Stop conditions
Do not add a feature if it adds navigation or data density without reducing effort, improving learning, increasing trust, or moving the user toward a real outcome.
